# Data Acquisition

This directory contains scripts for the acquisition and initial curation of molecular and bioactivity data from public chemical databases, primarily ChEMBL, as well as phytochemical mining workflows targeting Cannabaceae species.

The workflow is divided into three main stages: phytochemical mining, data retrieval, and data filtering.

## Files

### Input Files

**`molecules.csv`**

Contains ChEMBL assay IDs in a single column (`aidextid`). These identifiers are used by `parte2.py` to retrieve molecular and activity data from the ChEMBL API.

---

### Output Files

**`molecule_definitive.csv`**

Generated by `parte2.py`. Contains full activity-level and molecule-level information retrieved from the ChEMBL database.

**`molecule_filter.csv`**

Generated by `parte3.py`. Contains only rows where the `assay_description` field matches antioxidant-related keywords.

Filtered keywords:
- `Antioxidant`
- `antioxidant`
- `lipid peroxidation`

This dataset represents the initial antioxidant-focused subset used in the downstream data processing pipeline.

**`cannabaceae_phytochemicals_complete.csv`**

Generated by `mine_cannabaceae_phytochemicals.py`. Contains the enriched phytochemical dataset for Cannabaceae species, ready for downstream curation and QSAR prediction workflows.

---

## Source of Assay Identifiers

The file `molecules.csv` contains ChEMBL assay identifiers used as input for the retrieval pipeline. These identifiers originate from prior database searches within ChEMBL targeting bioassays associated with antioxidant activity and related biochemical processes.

## Part 1 — Cannabaceae Phytochemical Mining

### Script: `mine_cannabaceae_phytochemicals.py`

This script covers the **phytochemical data acquisition** block of the project. It is designed to mine, enrich, and organize compounds reported for Cannabaceae species, with a focus on:

- *Humulus lupulus*
- *Trema micrantha*
- *Cannabis* spp.

Its purpose is to assemble a structured phytochemical compound base from bibliographic references and external chemical queries, to be used as input for later stages of the QSAR workflow.

### What the Script Does

1. **Bibliographic reference integration** — incorporates a curated list of known compounds and academic references.
2. **Chemical query and enrichment** — queries PubChem and Entrez/PubMed to retrieve compound information.
3. **Taxonomic integration** — organizes compounds by plant or taxonomic source:
   - *Humulus lupulus*
   - *Trema micrantha*
   - *Cannabis sativa* and related groups
4. **Compound list expansion** — includes cannabinoids, terpenes, flavonoids, phenolic acids, triterpenes, and other relevant metabolites.
5. **Extended phytochemical table construction** — produces an output file with candidate compounds for downstream curation.

### Configuration

The following parameters must be reviewed and set before execution:

| Parameter | Description |
|---|---|
| `Entrez.email` | Required for NCBI Entrez API access |
| `Entrez.api_key` | Optional but recommended to increase rate limits |
| `SAVE_DIR` | Output directory for generated files |
| `OUTPUT_FILE` | Path for the main output CSV |
| `CACHE_DIR` | Directory for local caching of API responses |
| `FORCE_UPDATE` | If `True`, bypasses cached data and re-queries APIs |

> **Note:** This script requires local configuration before it can run correctly. Entrez credentials are mandatory for PubMed queries.

### Requirements

Python ≥ 3.8

Required libraries:
- `requests`
- `pandas`
- `tqdm`
- `pubchempy`
- `Bio.Entrez`
- `concurrent.futures`

### Execution

```bash
python mine_cannabaceae_phytochemicals.py
```

This step generates:
- `cannabaceae_phytochemicals_complete.csv`

A local cache directory is also created to accelerate repeated queries.

### Output

The primary output is `cannabaceae_phytochemicals_complete.csv`, containing the enriched phytochemical dataset for Cannabaceae species. This file feeds into downstream stages including manual curation, prediction dataset construction, QSAR modeling, and integrated chemical contribution analyses.

## Part 2 — ChEMBL Data Retrieval

### Script: `parte2.py`

### Data Retrieved

**Activity-level information:**
- Standard activity type, relation, value, and units
- pChEMBL value
- Data validity and activity comments
- Ligand efficiency metrics (when available)

**Assay metadata:**
- Assay description
- Assay type
- BAO format and label

**Target information:**
- Target identifiers
- Target organism

**Publication metadata:**
- Document identifiers
- Journal name
- Publication year

**Molecule-level information:**
- ChEMBL molecule ID
- Preferred molecule name
- Development phase (max phase)
- Canonical SMILES
- Molecular weight, ALogP, rule-of-five violations

### Workflow Overview

1. Load assay IDs from the input CSV file
2. Validate and clean assay identifiers
3. Query the ChEMBL Activity API for each assay
4. Detect and parse API responses in JSON or XML format
5. Extract activity records
6. Retrieve detailed molecule information via the ChEMBL Molecule API
7. Cache molecule data to avoid repeated API requests
8. Merge activity-level and molecule-level information
9. Append results incrementally to the output CSV file

### API Handling and Robustness

- Support for both JSON and XML API responses
- Automatic retry mechanism for failed API requests
- Request throttling to avoid exceeding API rate limits
- Local molecule-level cache to reduce redundant API calls
- Graceful handling of missing or incomplete data fields

### Requirements

Python ≥ 3.8

Required libraries:
- `pandas`
- `requests`

### Execution

```bash
python parte2.py
```

Generates: `molecule_definitive.csv`

## Part 3 — ChEMBL Antioxidant Assay Data Filtering

### Script: `parte3.py`

Filters the dataset to retain only antioxidant-related assays, supporting downstream data curation and QSAR modeling workflows.

### Filtering Criteria

Rows are kept only if the `assay_description` column contains at least one of the following keywords:
- `Antioxidant`
- `antioxidant`
- `lipid peroxidation`

### Input and Output

| File | Role |
|---|---|
| `molecule_definitive.csv` | Input — generated by `parte2.py` |
| `molecule_filter.csv` | Output — antioxidant-filtered dataset |

### Requirements

Python ≥ 3.8

Required libraries:
- `pandas`

### Execution

```bash
python parte3.py
```

Generates: `molecule_filter.csv`

## Role in the Project Pipeline

The datasets generated in this directory represent the **first stage of the data processing workflow**.

```
mine_cannabaceae_phytochemicals.py → cannabaceae_phytochemicals_complete.csv
                                                    ↓
                                          manual curation / prediction datasets

parte2.py → molecule_definitive.csv
                      ↓
            parte3.py → molecule_filter.csv
                                ↓
                          data/raw → data curation workflow
```

`molecule_filter.csv` is typically transferred to the `data/raw` directory, where it enters the data curation workflow. The Cannabaceae phytochemical dataset feeds into prediction and QSAR validation stages downstream.
